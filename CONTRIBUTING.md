# Contributing

Keep changes small, direct, and easy to review.

## Before Opening A Pull Request

- Check the repository README and existing scripts first.
- Match the code style already in the project.
- Include the smallest useful test or validation for the change.
- Keep unrelated formatting and cleanup out of the pull request.

## Pull Request Shape

- Explain what changed and why.
- Call out risk, migration steps, or follow-up work plainly.
- Link the issue when one exists.
- Prefer one focused pull request over a bundle of unrelated fixes.
